Tesseract

A lightweight, feature-rich launcher for Minecraft: Java Edition. Instances, mod loaders, modpacks, servers, and the tools that build a pack — in a desktop application that stays out of your way.

Free software under LGPL-3.0. Written in Python and PySide6.

The interface

A rail on the left, one page at a time, and the console below all of them.

Tesseract is a desktop application, and not a web page in a frame. These are design concepts, and not photographs of a finished product.

What it does

Instances

Keep as many separate installations as you want. Each one holds its own version, mods, worlds, and settings, in a directory that you can copy to another machine.

Four mod loaders

Install Fabric, Quilt, Forge, and NeoForge without leaving the launcher. Tesseract finds the loader build that fits the version.

Modpacks of Modrinth

Search 18,000 packs, choose a version, and play. Tesseract downloads every mod and builds the instance. A pack file from disk works as well.

The mods of an instance

Tesseract reads the name, the version, and the loader from inside each jar. A switch turns one mod off, with the same name that every other launcher understands.

Servers

An instance runs a server as well. Tesseract installs it for each of the four loaders, it asks for the agreement of Mojang, and the console sends commands to it.

One pack, three targets

A pack developer keeps a client, a server, and a pack file. Tesseract builds all three from one definition, and one press repairs each difference.

A lock file

The definition says what you want. The lock says which bytes that becomes, with a hash for each file. Two machines then install the same pack.

Export

Write a .mrpack file that another launcher installs, and a zip that the operator of a server opens into a directory.

One console

The log of the launcher and the output of each instance, in one place. A button moves the console into its own window, and another brings it back.

Shared assets

One asset store serves every instance, so ten instances do not cost ten copies of the same files.

Offline accounts

Play single-player with no sign-in and no network. An offline account keeps the same player UUID as the official launcher.

Light and dark

A theme that follows your choice, and remembers it. Every control carries an accessible name.

Without a window

The pack tools also run on the command line.

The window and the command line call the same core, so they give the same result. A script or a build job can therefore hold a pack.

Your Microsoft account

Tesseract signs you in. It never sees your password.

Tesseract asks for a Microsoft account for one purpose: to authenticate your own account, so that you can join online servers, and to confirm that the account owns the game. Single-player needs no sign-in at all.

The sign-in opens your own browser

Tesseract opens your system browser at the Microsoft sign-in page. It shows no embedded web view, and it never reads, stores, or transmits your password. This follows the advice of Microsoft for a native application.

How the flow works

Tesseract uses the OAuth 2.0 authorization code flow with PKCE, as a public client with no client secret. It requests the XboxLive.signin scope only.

Microsoft returns the authorization code to a short-lived HTTP server on the loopback address of your own machine. That server stops as soon as the code arrives.

Where the tokens go

The refresh token goes into the keyring of your operating system. Tesseract writes no token to a file and no token to a log. It sends no token and no personal data anywhere except to the endpoints of Microsoft.

Tesseract has no server, no telemetry, and no analytics of its own.
